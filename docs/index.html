Межі Кейси

kosmo-tui

Термінальний переглядач знімків викликів kosmo-trace/v1. Відповідає на одне питання: яка логіка і який шматок коду стоїть за кожним викликом. 

npx @ivlad003/kosmo-tui ./x.kosmo-trace.json
producer | npx @ivlad003/kosmo-tui -
npx @ivlad003/kosmo-tui ./x.kosmo-trace.json --print --trace t_cart

Потрібен Node >= 22.13.0. Мережі немає, залежностей під час запуску немає, у файл траси нічого не пишеться.

Вирішує

  • Показати дерево викликів у порядку запису, без пересортування.
  • Відкрити код з диска біля вибраного span, якщо файл лежить у корені проєкту.
  • Назвати шари Express, Nest, React, Next і HTTP так, щоб їх було видно в дереві.
  • Згрупувати виклики за module · feature.
  • Знайти помилку, стек, шлях між двома span і всіх, хто кликав той самий рядок.
  • Прочитати JSON, NDJSON, SQLite або потік NDJSON зі stdin.
  • Віддати текст, JSON або TSV для скрипта і CI через --print.
  • Не виконати escape-послідовності з траси і замаскувати очевидні секрети.

Не вирішує

  • Не записує траси. Потрібен окремий producer.
  • Не дебагер: не ставить breakpoint і не чіпляється до процесу.
  • Не заміна Jaeger, Tempo чи UI OpenTelemetry.
  • Не профайлер CPU чи пам'яті.
  • Не live-tail: потік читається до EOF, модель будується один раз.
  • Не вгадує батька span і не лагодить код.
  • Не гарантує, що кожен секрет замасковано.
  • Не читає код з /, з домашньої директорії чи вище неї, якщо ви самі не задали --root.

Коли його відкривати

Є файл або потік kosmo-trace, і треба зрозуміти, який виклик упав, у якому файлі, і чи це ваш код, чи шар фреймворка. Якщо траси ще немає, kosmo-tui нічим не допоможе: він тільки читає вже записаний знімок.

Маскування в переглядачі — другий шар. Секрет у полі з невинною назвою він не зловить. Producer має маскувати значення в момент запису.

Покрокові кейси, клавіші і --print — у інструкції.
